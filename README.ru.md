# OneTrace.pro для 1С-Битрикс

Подключает магазин на «1С-Битрикс: Управление сайтом» к [OneTrace.pro](https://onetrace.pro) — платформе данных о клиентах (CDP): заказы, покупатели и согласия на рассылку с сервера, трекер сайта, просмотры товаров, каталог, виджеты рекомендаций, Web Push и письма магазина. Цепочки брошенной корзины, просмотра без покупки, после покупки и возврата клиентов, рекомендации и прогнозы работают сразу после подключения.

[English version](README.md)

- «1С-Битрикс: Управление сайтом» с модулями «Интернет-магазин» и «Торговый каталог» (редакции «Малый бизнес» и выше), PHP 8.2–8.5, UTF-8
- Заказы и их статусы отправляются с сервера через очередь с повторами (агент раз в минуту): оформление заказа никогда не ждёт платформу
- Настройки по сайтам: каждый сайт можно подключить к своему проекту
- Те же события и свойства, что у всех плагинов OneTrace для магазинов, на основе [onetrace-php](https://github.com/OneTracePro/onetrace-php) — библиотека внутри модуля

## Что передаётся

| Данные | Когда | Как |
|---|---|---|
| `identify` — email, телефон, имя, город, страна, язык | регистрация, вход, изменение профиля, каждый заказ | сервер, секретный ключ |
| Согласие на рассылку | подписка и отписка в модуле «Email-маркетинг»; свойство заказа «Да/Нет» в оформлении | сервер, вместе с `identify` |
| `order_completed` | заказ оформлен (любое оформление, админка, API) | сервер |
| `order_paid`, `order_refunded`, `order_cancelled` | заказ оплачен, оплата возвращена, заказ отменён | сервер, один раз на событие заказа |
| `order_shipped` — служба доставки, трек-номер, ссылка на отслеживание, товары посылки | отгрузка передана в доставку: отгружена («Отгружено») или в статусе «Отгружен» | сервер, один раз на отгрузку (вторая посылка — новое событие) |
| `order_delivered` | заказ перешёл в статус доставленного (по умолчанию «Выполнен», настройка «Статусы заказа „Доставлен“») | сервер, один раз на заказ |
| `add_to_cart`, `remove_from_cart`, `checkout_started` | изменения корзины и страница оформления (sale.order.ajax) — для посетителей с cookie трекера или вошедших | сервер |
| `add_to_wishlist`, `remove_from_wishlist` | товар корзины отложен («Отложенные» — избранное Битрикса), возвращён в корзину или удалён из отложенных | сервер |
| `product_viewed` | страница товара: счётчик просмотров стандартных шаблонов catalog.element | сервер, работает с композитным кэшем |
| Просмотры страниц | витрина | трекер в браузере |
| Каталог товаров | изменения товаров, цен и остатков (заказы, отмены, админка, складские документы), раз в сутки и кнопка «Выгрузить весь каталог» | сервер, `products.write` |
| `search` | первая страница результатов поиска по каталогу при включённом «Поиске по товарам» | сервер |

У каждого заказа Битрикса есть пользователь (оформление без регистрации создаёт его), поэтому заказы, корзина и учётная запись попадают в один профиль; браузер, в котором оформили заказ, сохраняется с заказом — по нему идут и последующие события (оплата, возврат).

## Установка

1. Скачайте `onetrace.connector.zip` из [последнего релиза](https://github.com/OneTracePro/onetrace-bitrix/releases) и распакуйте в `/local/modules/` (папка `onetrace.connector`).
2. **Marketplace → Установленные решения**: установите «OneTrace — платформа данных о клиентах».
3. В проекте OneTrace откройте **Ключи API** и создайте ключ записи (для витрины) и секретный ключ с правом `products.write` (для сервера); для писем магазина добавьте право «Отправка сообщений вручную» (`messages.send`).
4. **Настройки → Настройки продукта → Настройки модулей → OneTrace**: на вкладке каждого сайта укажите адрес платформы (домен, по которому вы открываете OneTrace) и оба ключа, нажмите **Проверить подключение**.
5. Переведите агенты на cron (`agents_use_crontab`), иначе очередь ждёт посещений сайта.

Обновление: распакуйте новую версию поверх папки и один раз нажмите **Сохранить** в настройках — так устанавливаются новые компоненты и обработчики событий версии (`/bitrix/components/onetrace/`).

## Отгрузки и доставка

По этим событиям онлайн-чат платформы отвечает на вопрос «где мой заказ», поэтому главное в них — трек-номер.

- **`order_shipped`** — для каждой отгрузки заказа, кроме системной, когда она отгружена (флаг «Отгружено» в заказе) или получила статус отгрузки «Отгружен» (`DF` или статус, который модуль «Интернет-магазин» ставит при отгрузке). В событии — название службы доставки, как его видит покупатель (у «Без доставки» — нет), трек-номер, ссылка на отслеживание, если у службы доставки есть отслеживание (Почта России и модули доставки с классом отслеживания), и товары отгрузки. Вторая посылка заказа — отдельное событие; повторное сохранение отгрузки или смена трек-номера нового события не дают.
- Отгрузка, переданная **без трек-номера**, ждёт его в очереди до 12 часов: номер, введённый за это время вручную или модулем доставки, уходит с событием; потом событие уходит без него, и номер, введённый позже, повторно его не отправляет.
- **`order_delivered`** — заказ перешёл в один из статусов настройки сайта **Статусы заказа «Доставлен»** (несколько — с зажатым Ctrl; по умолчанию «Выполнен», `F`; ни одного — событие не отправляется). Переход между этими статусами второго события не даёт.

## Письма магазина

Письма магазина — о заказах, регистрации, восстановлении пароля, письма модулей магазина — могут уходить через почтовую интеграцию проекта OneTrace: статусы доставки, история в профиле покупателя, ваш домен и его репутация. Настраивается это в OneTrace, раздел **Письма магазина** («Отправлять письма магазина через OneTrace» и шаблоны OneTrace для писем о заказе); модуль читает эти настройки по секретному ключу (право «Отправка сообщений вручную») раз в 5 минут и при сохранении настроек модуля и показывает их на вкладке каждого сайта (только просмотр).

- **Где:** `main:OnBeforeEventSend` — для каждого почтового шаблона почтового события Битрикса до того, как Битрикс соберёт и отправит письмо. Модуль собирает письмо так же, как Битрикс (тема, тело, From, Reply-To, CC, BCC, вложения шаблона и события), и передаёт его платформе — по запросу на получателя (таймаут 5 секунд, без повторов, ключ идемпотентности на событие, шаблон и получателя).
- **Как есть:** тема, HTML (текстовое письмо — экранированным HTML с кликабельными ссылками; относительные ссылки HTML-письма становятся абсолютными), текст, имя отправителя, Reply-To, язык сайта и вложения (PDF, PNG, JPEG, GIF, текст, CSV, календарь; до 5 файлов и 5 МБ — с другими письмо остаётся Битриксу).
- **Шаблоны заказа:** письмо о заказе вида, для которого включён шаблон OneTrace, уходит покупателю данными заказа — номер, страница заказа (гостевая ссылка, если разрешена, иначе `/personal/order/detail/<номер>/`), строки с картинкой, ссылкой, артикулом и свойствами, итоги, оплата и доставка, адрес из свойств заказа, отслеживание отгрузки, причина отмены, сумма возврата, — а письмо на языке сайта собирает OneTrace.
- **Копии сотрудникам:** копии на адреса магазина (CC, BCC, адрес отправителя сайта или главного модуля, адрес для заказов «Интернет-магазина», «Копии всех писем») никогда не уходят через OneTrace, даже с включённой пересылкой — иначе платформа заведёт профили покупателей на адреса сотрудников; они остаются в письме Битрикса.
- **Запасной путь:** получатели, которых принял OneTrace, убираются из письма; остальным (и копиям сотрудникам) письмо отправляет сам Битрикс — нет секретного ключа или права, платформа недоступна, исчерпана квота сообщений (402), неверные данные (422), слишком много писем получателю (429), вложение, которое платформа не принимает. В оставшемся письме каждый адрес один раз: адрес из To убирается из CC и BCC (и из BCC, который Битрикс добавляет для «Копий всех писем», — через `main:OnBeforeMailSend`); если покупателей не осталось, копия сотруднику становится To. Если всё отправлено, почтовое событие отмечается отправленным.

| Почтовое событие Битрикса | Вид письма |
|---|---|
| `SALE_NEW_ORDER`, `SALE_NEW_ORDER_RECURRING` | `order_placed` |
| `SALE_ORDER_PAID` | `order_paid` |
| `SALE_ORDER_DELIVERY` («доставка разрешена»), `SALE_ORDER_TRACKING_NUMBER` | `order_shipped` (отгрузка события) |
| `SALE_STATUS_CHANGED_<статус>` | `order_delivered` для статусов настройки «Статусы заказа „Доставлен“», иначе `order_note` |
| `SALE_ORDER_CANCEL` | `order_cancelled` |
| `SALE_ORDER_REMIND_PAYMENT`, `SALE_ORDER_ALLOW_PAY`, `SALE_ORDER_SHIPMENT_STATUS_CHANGED` | `order_note` |
| `SALE_CHECK_PRINT` | `invoice` |
| `USER_PASS_REQUEST` | `password_reset` |
| `USER_INFO`, `USER_INVITE`, `NEW_USER` | `account_new` |
| `NEW_USER_CONFIRM`, `SUBSCRIBE_CONFIRM`, `SENDER_SUBSCRIBE_CONFIRM` | `email_verification` |
| `USER_CODE_REQUEST`, `CATALOG_PRODUCT_SUBSCRIBE_LIST_CONFIRM` | `login_code` |
| `USER_PASS_CHANGED`, `NEW_DEVICE_LOGIN`, другие `SALE_*` и `CATALOG_*` | `other` |
| Копия на адрес магазина: CC, BCC, адрес отправителя сайта или главного модуля, адрес для заказов «Интернет-магазина», «Копии всех писем» | никогда не через OneTrace: отправляет Битрикс (иначе платформа заведёт профили покупателей на адреса сотрудников) |
| События других модулей (форум, блог, журнал событий, обратная связь …) | не затрагиваются |

Для некоторых событий заказа у Битрикса нет письма; если их шаблон OneTrace включён, **модуль отправляет их сам** из очереди (с повторами, как события), по одному разу: `order_shipped` отгрузки, переданной в доставку (после трек-номера или 12 часов ожидания, как событие), если Битрикс не отправил для неё своё письмо с трек-номером или «доставка разрешена»; `order_delivered`, если статус «Доставлен» не отправляет письмо Битрикса (флаг «Оповещать» выключен или шаблон неактивен); `order_refunded` для возвращённой оплаты.

## Каталог

В каталог попадают товары инфоблоков торгового каталога, привязанных к сайту. Торговые предложения — не отдельные товары: предложение выгружает свой товар, а товар с предложениями получает наименьшую цену предложения. Цена — та, что платит гость со скидками; старая цена — до скидок. Категории — разделы элемента с родителями; бренд — свойство `BRAND`, `BRAND_REF` или `MANUFACTURER`; характеристики — свойства умного фильтра.

Остаток (`stock`) передаётся у товара с количественным учётом, которого нельзя купить при нулевом остатке, — в товаре или, при значении «по умолчанию», в настройках модуля «Торговый каталог»; товар с предложениями передаёт сумму остатков активных предложений, если учёт ведётся у каждого и ни одно не продаётся при нулевом остатке. Товары без учёта или с разрешённой покупкой при нулевом остатке передаются без остатка: для них ноль не значит «нет в наличии». Изменение количества — заказ, его отмена, правка в админке, складской документ — выгружает товар заново. Платформа учитывает остаток, только если в её настройках каталога включено «Учитывать остатки из API и плагинов»: тогда нулевой остаток снимает товар с продажи и работает триггер «осталось мало».

## Избранное и «Сообщить о поступлении»

- **Избранное.** Своего избранного в Битриксе нет, его роль играют отложенные товары корзины («Отложенные», кнопка «Отложить» в `sale.basket.basket`): отложенный товар — `remove_from_cart` и `add_to_wishlist`, возвращённый в корзину — `remove_from_wishlist` и `add_to_cart`, удалённый из отложенных — `remove_from_wishlist`. События работают в цепочках снижения цены и поступления товара. Если в теме своё «Избранное», отметьте его кнопки для трекера (1.13.0 и новее): `data-cdp-wishlist="{id товара}"` на «добавить» и `data-cdp-wishlist-remove="{id товара}"` на «убрать».
- **«Сообщить о поступлении».** Добавьте компонент в шаблон страницы товара (`bitrix:catalog.element`, `template.php` вашего шаблона) рядом со стандартной кнопкой «Подписаться» `bitrix:catalog.product.subscribe`:

  ```php
  $APPLICATION->IncludeComponent('onetrace:catalog.notify', '', ['PRODUCT_ID' => $arResult['ID']], $component, ['HIDE_ICONS' => 'Y']);
  ```

  Для товара, который нельзя купить, он выводит `<div data-cdp-notify="{id товара}"></div>` (предложение — id своего товара), и трекер рисует там форму «Сообщить о поступлении» проекта («Сайт → Формы» платформы); платформа сообщит покупателю, когда товар появится. Настройка «Показывать форму «Сообщить о поступлении»» выключает её для сайта. Стандартную кнопку подписки после этого можно убрать: удалите её компонент из шаблона или выключите параметр шаблона «Разрешить оповещения для отсутствующих товаров» (`PRODUCT_SUBSCRIPTION`) компонента каталога. Своего кэша у компонента нет: в кэшируемом `catalog.element` он кэшируется вместе со страницей товара, которую Битрикс сбрасывает при изменении наличия.

## Поиск по товарам

Включите **Поиск по товарам** в настройках (поиск должен входить в тариф проекта) и замените компонент на странице поиска каталога — в шаблоне комплексного компонента `bitrix:catalog` это `search.php`:

```php
$APPLICATION->IncludeComponent('onetrace:catalog.search', '', $params…); // вместо 'bitrix:catalog.search'
```

- Параметры те же. Товары, их порядок и количество берутся из OneTrace — словоформы, опечатки, запрос в неверной раскладке, интересы посетителя — и показываются компонентом `catalog.section` вашего магазина. Сортировка по цене передаётся платформе.
- Запрос с правилом переадресации («Сайт → Поиск» платформы, например «доставка» → страница доставки) открывает страницу правила.
- В полях поиска магазина (`search.title` и формы с `q`) при вводе — подсказки трекера вместо всплывающего списка Битрикса.
- При любой ошибке платформы работает `bitrix:catalog.search`.

## Языки каталога

Каталог проекта берётся из его первого сайта. Остальные сайты, подключённые к тому же проекту (тот же адрес и секретный ключ), на другом языке — со своими копиями каталога, как их создаёт обмен с 1С: товары и разделы с тем же `XML_ID` добавляют переводы — названия, ссылки на этом сайте и значения характеристик. Платформа показывает рекомендации, виджеты, результаты поиска и письма на языке посетителя.

## Бонусные баллы

Включите **Бонусные баллы** в настройках (программа лояльности проекта должна быть активна, у секретного ключа — права `loyalty.read` и `loyalty.write`) и выберите, как баллы попадают в заказ:

- **Оплата баллами** — цены не меняются; у заказа появляется вторая, оплаченная оплата платёжной системой модуля «Оплата баллами» (неактивна, покупатели её не выбирают), а в итогах оформления — «Оплачено» и «Осталось оплатить». Возвраты и учёт видят баллы как оплату.
- **Скидка на товары заказа** — баллы пропорционально снижают цены строк, при оформлении видна экономия. Подходит, если в магазине у заказа должна быть одна оплата.

На странице оформления (`sale.order.ajax`, любой шаблон) над итогом заказа появляется блок: баланс, сколько баллов можно списать в этом заказе (доля задаётся в программе) и сколько баллов начислится. Покупатель, вошедший на сайт, списывает баллы, гость видит ссылку для входа. Баллы удерживаются на 30 минут и удерживаются заново при изменении корзины; оформление заказа подтверждает их с номером заказа, неудавшиеся подтверждения повторяет агент. Сумма `order_completed` — то, что оплачено деньгами.

Свои баллы покупатель видит на странице личного кабинета с компонентом:

```php
$APPLICATION->IncludeComponent('onetrace:loyalty.account', '', []);
```

— баланс, баллы, которые станут доступны после срока возврата, история и кнопка «Вступить» для тех, кто ещё не участник.

## Промокоды

Пулы промокодов настраиваются в разделе **Промокоды** платформы; скидку даёт правило работы с корзиной магазина (**Магазин → Маркетинг → Правила работы с корзиной**, с купонами). Привяжите правило к пулу в настройке сайта «Промокоды», по одному в строке:

```
welcome = 12
```

Каждые 5 минут (агент) новые и изменённые уникальные коды пула становятся купонами правила на один заказ со сроком кода. Купоны других правил с тем же кодом не трогаются; пулы с общим кодом не синхронизируются — добавьте такой купон в правило сами. События заказов передают купон, и платформа учитывает использование. Секретному ключу нужно право `promo.read`.

**Приглашения** (при включённых бонусных баллах): новый пользователь с cookie `cdp_ref` трекера (ссылка `?ref=`) — код друга уходит на платформу, и друг получает подарок; пригласивший — баллы за первый заказ друга. Компонент `onetrace:loyalty.account` показывает реферальную ссылку и действующие промокоды покупателя.

## ИИ-бот чата: MCP магазина

ИИ-бот чата OneTrace отвечает покупателям живыми данными магазина и, если вы разрешите, выполняет действия с заказами. Включите **Подключить к боту чата** в блоке «ИИ-бот чата: MCP магазина» сайта в настройках модуля и сохраните: модуль подключит свой MCP-сервер (`/bitrix/services/onetrace.connector/mcp.php?site=s1`, контракт MCP магазина v1, HTTPS) к боту проекта. Сайты одного проекта используют одно подключение. Секретному ключу нужно право `chats.manage`.

- **Чтение** (включено по умолчанию): заказы покупателя (аккаунта и других аккаунтов с его email — их создаёт оформление заказа без входа), заказ с позициями, оплатой, службой доставки, адресом и трек-номером со ссылкой, наличие и цены каталога с торговыми предложениями, активные службы доставки (цена и срок у настраиваемых), текст и страница условий возврата из настроек.
- **Действия** (выключены, разрешите их в «Что может бот»): отмена заказа, по которому ничего не оплачено и не отгружено (как в личном кабинете), заявка на возврат или смену доставки в магазин — комментарий менеджера к заказу и почтовое событие `ONETRACE_STORE_MCP_REQUEST` на адрес заказов магазина. Бот выполняет действие только после согласия покупателя в чате.
- **Покупатели**: вошедшие на сайт подтверждаются автоматически — вход ставит cookie `onetrace_chat`, и скрипт трекера получает подписанный токен у `chat-customer.php` (токен не попадает в страницы композитного кэша); гости и покупатели из мессенджеров получают код из 6 цифр почтовым событием `ONETRACE_STORE_MCP_CODE` (обработчик `onetrace.connector:onStoreMcpSendCode`, вернувший успешный результат, отправляет код сам, например по SMS). Заказы других покупателей — «не найдены».

## Рекомендации и Web Push

- Виджеты из раздела **Сайт → Виджеты** платформы: разместите компонент **Рекомендации OneTrace** (`onetrace:recommendations`) на странице товара, в корзине или на любой странице и укажите идентификатор виджета; передайте id товаров страницы (`ITEMS`) и раздел (`CATEGORY`), если они нужны виду виджета.
- Web Push: включите в настройках — модуль отдаёт `/cdp-sw.js` с корня сайта (правило `urlrewrite.php`).

## Конфиденциальность

- Согласия берутся из подписок самого магазина; галочка в оформлении заказа учитывается, если указать код её свойства заказа в настройках.
- Выход из учётной записи забывает посетителя трекера в браузере: следующий человек за этим компьютером начнёт новый профиль.
- Уже переданные данные остаются в проекте OneTrace; профили удаляются там (GDPR).

## Разработка

```bash
composer install
tests/env/run.sh                       # интеграционные тесты: «Малый бизнес» в Docker, PHP 8.3
PHP_VERSION=8.2 tests/env/run.sh       # другой PHP (в tests/env сначала docker compose down -v)
tests/env/smoke.sh                     # витрина по HTTP
php bin/build.php                      # dist/onetrace.connector.zip и dist/marketplace.zip
```

Тесты скачивают пробный дистрибутив «Малого бизнеса» (последнюю версию), проходят мастер установки без браузера (`tests/env/wizard.py` на основе [BitrixBox](https://github.com/razzhivine/bitrixbox), MIT) и ставят модуль из рабочей копии: заказы проходят через API модуля sale (корзина, отгрузка, оплата), подписки — через модуль «Email-маркетинг».
